# Fixed100 methods review boundary (#376/#377)

The existing v4 methods are a frozen **exploratory review candidate**. They do
not authorize `supported_history_threshold`. NEWMARKET's conditional outcomes
were inspected before v4; NEWMARKET is an inspected pilot. A subsequent review
cannot make its analysis prospective. The other fixed issuers are retained,
including unavailable or incomplete cases; they are not a replacement cohort.

The readiness command records the exact bytes digests of
`issue-377-methods-v4.json` and `issue-377-protocol-proposal-v3.json` in its input
identity and report. Any edit changes the report identity. It also records the
explicit conditional evidence index, runtime, exact clean commit and consumed
archive members. No implicit directory scan chooses the newest or best result.

The v4 method owns the analysis definitions: two registered models, revenue and
undiscounted FCFF targets, paired three/four/five-year arms, common training-only
scale, a naive baseline, issuer-level resampling and multiplicity across 32
hypotheses. Missing/zero scales retain raw errors but cannot supply scaled
losses. Scenario comparisons do not supply exact labels or independent issuer
observations. Both models share the #352 arithmetic, so numerical agreement is
not independent predictive corroboration.

All-selected coverage has denominator 100. Exact error and paired history
comparisons have their actual eligible denominators. The frozen normalized
inventory has at most 90 eligible annual labels: nine have no later annual
period retained and one has a 731-day horizon mismatch. This is not proof of
raw SEC completeness. The infeasible legacy requirement of 100 complete pairs
is not silently lowered. Observed interval precision is not retrospective power.

Promotion remains disabled. Before any confirmatory threshold claim, an actual
independent method/business review must address the unapproved numerical
margins, primary policy, replacement of the legacy complete-pair gate,
finite-sample interval adequacy, missingness/generalization scope, inspected
pilot handling and authenticated release-bound inputs/labels. The v3 proposed
MASE/noninferiority/precision/power numbers are proposals, not external
standards. New methods must disclose prior outcome inspection and cannot select
favorable observed outcomes. Review of engineering code or a project signature
alone does not supply accounting or statistical approval.

## Readiness audit ownership and interpretation

`scripts/audit_history_study_readiness.py` owns an offline join. It reuses the
existing frozen-label selector and conditional evidence exporter. Fundamental
Service owns the actual scenario forecast, label and comparison operations;
the audit introduces no financial arithmetic, mapping approval or release path.
It uses the existing locked, content-addressed atomic report publisher, outside
Git only. No source download, database write, trust change or snapshot publication
is performed. Docker/service acceptance of the underlying operations remains
separate; an offline readiness report does not certify a deployed service.

An alternative that restored the archived forecast/mapping pipeline was rejected
because it would restore removed arithmetic/authorization paths. Reading the
pinned archive without extraction preserves historical evidence with a smaller
ownership surface. Corrupt members, duplicate targets/fields, substituted issuer
or period identities, omitted evidence and future decision inputs fail closed.

Every one of the 100 issuers and 589 filing targets is retained. Target rows keep
accession, period, available-at, original/amendment status and role. Archived
mapping dispositions link back to complete packets/proposals, including fact
IDs, concepts, unit, scope, source hashes and mapping versions. Companyfacts
candidate gaps describe that profile; they do not prove absence from original
filings or permit zero imputation.

The archived integrity/lexical observations originate in an earlier execution
than the fixed original outcome references. They are linked by identical filing
targets and retain their own result digests. Their failures are historical
diagnoses, never current parser verdicts. A null failure code is recorded as
"no failure code recorded", never a passing source. Current parser validation
is explicitly not rerun by this command. The supplied NEWMARKET conditional
artifacts are instead recomputed through the current formal operations, under
matching runtime pins. All other issuers are marked "evidence not supplied in
the explicit index", not falsely diagnosed as absent from every local source.

The resulting audit can prioritize source and mapping work. It cannot establish
forecast accuracy or promote history length. `verified_issuers=0`, exact cases
remain 0/100 and the threshold remains null until the owning gates pass.
