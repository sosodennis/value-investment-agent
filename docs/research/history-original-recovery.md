# Retained original ZIP receipt recovery

This #376 diagnostic increment follows the fixed100 candidate batch. It recovers
actual SEC ZIP response receipts for the 26 already blocker-free results in the
complete 187-filing size-refusal corpus. Eligibility uses the frozen parser
outcome, before forecasts or errors. All 187 results remain in the report.
It does not establish that these 26 filings form complete issuer histories.

`read_retained_history_corpus.py` verifies the fixed manifest, complete selection
and parser corpora, per-filing envelopes and original result references, profile
and resource pins, fact and parser digests and original blockers before I/O.
`recover_history_originals.py` owns CLI composition and external recovery state.
It uses Fundamental Service's formal SEC request/retention adapters, bounded ZIP
reader, original-issuer evaluator and existing atomic report publisher. The
shared ZIP reader is public; its service behavior and security limits are
unchanged. No mapping/release, formula or valuation policy changes are made.

Each successful source has the original accession ZIP URI, actual HTTP status,
capture time, response headers, byte count and ZIP hash. The parser input hash
identifies the exact selected XML member. Every selected member is checked
against its frozen hash and length. A source mismatch is a retained failure.
The old direct XML and ZIP differences and missing old receipts remain visible;
a new ZIP receipt does not certify direct/ZIP semantic equivalence.

The typed parser report reconstructs an old pinned execution. It is not a new
Arelle run or a historical regulatory-applicability certificate. Its path and
`parsed_at` are normalized to the ZIP receipt by the existing original-issuer
contract; neither is represented as the old parser's execution time. The old
runtime, profile, cache and report digests remain separately bound in evidence.
Original-issuer evidence grants no security, mapping or release authority.

The CLI requires an exact clean commit. Pass the existing SEC contact through
`FUNDAMENTAL_SEC_USER_AGENT` for explicit `--allow-network` use; do not put contact
values into command logs. Without that flag, a missing successful receipt fails
with `NETWORK_DISABLED` and does not create a permanent source-failure result.
Do not strip spaces from the User-Agent or invent a capture receipt.

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=fundamental-service/src:scripts \
  python -B scripts/recover_history_originals.py \
  --exact-commit "$ISSUE_COMMIT" \
  --manifest "$FIXED_MANIFEST" \
  --selection "$FROZEN_SELECTION" \
  --parser-report "$FROZEN_PARSER_REPORT" \
  --results "$FROZEN_PARSER_RESULTS" \
  --source-repository "$PRESERVED_ORIGINAL_REPOSITORY" \
  --base-index "$EXISTING_BATCH_INDEX" \
  --output-directory "$EXTERNAL_RECOVERY_DIRECTORY" \
  --allow-network
```

Generated bytes must stay outside all Git checkouts. Successful receipts and
content are retained before parser reconstruction. The service cache deduplicates
by CIK/accession/origin/source profile and original URI. A process lock and
immutable attempt artifact retain failures too; an identical attempt does not
retry a failure. A deliberate new acquisition policy requires a new protocol
identity, not an ad hoc overwrite. An interrupted import reuses its source and
completes missing typed evidence. Existing identical reports are not rewritten.
