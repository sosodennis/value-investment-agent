## Test data and reset scope

The temporary PostgreSQL database `via_issue192_e2e` belongs to the isolated
`value-investment-agent-192-test` Compose project. The synthetic-only database
was dropped after the 100-key browser acceptance and recreated for manual
staging verification. It currently contains the local test account and the two
staging keys configured in the local `.env`, encrypted by the running Provider
Service. No production data or 100-key synthetic batch remains in this
database. The canonical browser account and synthetic inputs are generated by
the acceptance harness; the LLM Provider Service creates its owned-key tables
at startup. The current Fernet key exists only in the running process; recreate
this disposable database before restarting the Provider Service.

Rebuild it by starting the Compose project's PostgreSQL and Redis services,
creating `via_issue192_e2e`, and running
`finance-agent-core/.venv/bin/python -m src.infrastructure.migrations.cli`
with `POSTGRES_DB=via_issue192_e2e`. The LLM Provider Service creates its owned
tables during startup. To restore a blank database, drop and recreate only
`via_issue192_e2e` and rerun these migrations. The separate pre-existing
`langgraph` database was inspected and preserved; it contains unrelated local
acceptance data.
