# Original SEC response retention for #361

Pinned-accession production acquisition uses `RetainedSecSourceAdapter` before provider I/O. Each receipt key contains the versioned receipt protocol, normalized CIK, original accession, valuation timestamp, source-selection policy and exact URI. Captured time is receipt metadata, never identity. Different models, reviewed mappings or validation runtime revisions can reuse the same original response without downloading it again.

The service stores exact response bytes by content hash and an immutable canonical receipt in its existing content/artifact stores. Receipts retain status, media type, original capture time, retained response headers and declared/received sizes. PostgreSQL advisory locks serialize capture for the same key before checking the receipt or downloading. A contending request receives a retryable error. The acquisition lock still protects snapshot publication separately.

A retry or process restart reads the receipt and verifies scope, URI, artifact state, content hash and byte length. Valid receipts produce no content/artifact writes. Corrupt or missing retained bytes fail closed instead of silently fetching replacement bytes. Partial upstream response failures do not produce a successful receipt; a later attempt may retry provider I/O. A crash between receiving bytes and committing their receipt may also require retrying that capture. Content-addressed storage prevents duplicate retained evidence.

`SecAcquisitionUseCase` passes the retained adapter into the existing ingestion service for the index, original entrypoint and accession ZIP. The request-local adapter avoids mutating shared ingestion state. Stable original receipt times determine the acquisition capture time. A later parser or mapping rejection therefore retains the same raw evidence for another attempt. The runtime factory uses the existing PostgreSQL content/artifact stores; it does not need new volumes, migrations or credentials. Unpinned contemporary discovery keeps its existing behavior.

This change does not approve mappings, establish historical security identity, publish failed snapshots or bypass regulatory validation. The separate [original-filing identity contract](issue361-historical-identity.md) avoids present-day ticker membership only when original DEI security evidence can be checked; complete2016 cover-page support remains an open #371 gap. Original sample diagnostics use an explicitly nonpublishable CIK-bound identity and do not establish a canonical replay. Full fixed-cohort replay and thresholds remain unapproved. Full acquisition `execute()` still records per-attempt operational audits; this source-reuse evidence does not establish idempotency of those rows.
