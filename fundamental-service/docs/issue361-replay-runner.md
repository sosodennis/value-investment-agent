# Release-bound history replay

`history_forecast_replay.run_history_replay(application, plan)` calls the existing public `FundamentalApplication` snapshot, policy, evidence-read, preparation and calculation methods. It accepts immutable origin/release/model/policy pins, never caller valuation assumptions. The calculator's `revenue_1` and `fcff_1` nodes supply forecasts. Service-owned uncertainty and calculation evidence remain attached.

A calibration plan must match the fixed cohort manifest digest, all 100 original issuer/accession decisions and timestamps, the full frozen filing inventory and both predeclared models. Validation runs before service reads. Engineering fixtures use an explicit `evidence_class=engineering`; their results cannot establish a production threshold. Origins and filing inventories are normalized chronologically. Duplicate origins or models fail before execution.

The fixed manifest digest is pinned in the runner independently of its storage location. `run_history_replay(..., cohort_root=ROOT)` and CLI `--cohort-root ROOT` locate the unchanged `docs/acceptance/issue-359-*` corpus under an explicit root. This supports installed service packages whose module path does not contain repository evidence. The manifest, protocol, frame and issuer snapshot hashes are checked before service reads; moving identical evidence does not change artifact digests. A different cohort is rejected before accessing files. The production CLI still requires the clean committed source checkout for Git and runtime authentication; this input-location option does not make the source-only image a Git checkout.

For each origin, pin the forecast snapshot ID, snapshot digest, data-release digest and source-policy version. Pin the mapping version and each model/policy ID, version and digest. The runner checks snapshot issuer/time/source availability, release-bound fact evidence, policy availability, composer bindings and the calculator's policy trace. The service evidence reader validates actual release mapping digests, approval and fact bindings, and returns its checked mapping version. Both forecast and OOS label evidence must match the fixed plan's mapping version before targets can be scored. A changed or future pin produces an explicit abstention, retained in the original denominator. Missing releases are retained and cause no fabricated service call. Unexpected programming errors abort instead of becoming financial observations.

All forecasts finish before any label read. Labels use the first subsequent original annual filing in the frozen inventory, with an annual horizon matching the one-step forecast. Only its exact original accession can supply label facts; amendments and later comparative publications remain excluded. The existing annual-history resolver and historical-metric owner derive actual FCFF from filed NOPAT and net reinvestment, with all constituent fact IDs and source references. No valuation or policy formula is moved into the replay/report module. Conservative existing completeness/conflict gates still apply; a revenue label alone is explicitly incomplete.

Outputs are canonical `input`, `forecast`, `label`, `score` and `report` artifacts. Per-origin scores retain forecast/actual values, residuals, absolute/percentage errors and missing reasons. Zero label denominators leave percentage errors null. Reports retain both model denominators, provisional/verified/abstain dispositions, complete-label counts, independent issuer counts, MAE/RMSE and descriptive issuer-cluster standard errors (undefined below two independent issuers). Statistical reductions use a fixed Decimal context. `write_history_replay` reuses the existing atomic content-addressed writer and does not rewrite matching artifacts.

Replay protocol `release-bound-history-replay-v2` pins `history-length-evidence-v1` in the input. Explicit v1 plans are rejected; regenerate the plan with the new protocol and exact runtime pins. Earlier v1 artifacts remain unchanged and retain their original digests. The Python plan class remains `HistoryReplayPlanV1`; the protocol field versions the replay semantics.

For each model, the report groups all origins by observed complete trailing annual history from the service's operating-margin metrics, retaining every length from zero through the service requirements window and an unknown group. An upstream refusal with no resolved metrics is unknown, including a missing release or missing required facts. Zero is reserved for a resolved metric result with no complete operating-margin period. These descriptive groups do not refit each issuer at three versus five years or establish a causal history-length comparison. Each group retains its own coverage, issuer counts, errors, uncertainty and missing reasons.

`execution_status` distinguishes blocked, partial and complete forecasts with complete revenue/FCFF label pairs. `empirical_status=not_measured` means no complete pairs; `empirical_underpowered` means positive pairs from fewer than the existing 100-independent-issuer floor; `measured_review_required` means that floor was reached. The floor is not sufficient for promotion. `threshold_decision` separately retains engineering-only runs, engineering blocks and forecasts without complete labels. All thresholds remain null because reviewed accuracy/power criteria and a reviewed history-length comparison/promotion policy are absent. Per-origin service quality remains verified, provisional or abstain as returned by the service.

This runner does not publish snapshots, approve mappings, activate policies/releases or promote a history threshold. `supported_history_threshold` remains null pending genuine cohort execution and an approved threshold-promotion protocol. Passing synthetic composer/calculator fixtures, including unchanged service artifact inventories, is engineering evidence only. A runtime command that binds actual reviewed historical releases and the complete SEC replay remains an open #361 acceptance gate.

The production CLI is `fundamental-history-forecast-replay --plan PLAN --output-directory OUTPUT`. It checks clean committed source and exact runtime pins (`replay_runtime_pins()`), requires the fixed calibration cohort, and starts the existing production runtime composition with its configured metadata, stores and trust roots. It does not offer fixture fallback. Keep service credentials in the normal runtime environment. A plan is canonical `HistoryReplayPlanV1` JSON, with every origin present even when its forecast/label release pin is null. Missing reviewed releases remain explicit abstentions and cannot establish forecast execution. Merely generating an empty-release plan/report is not full replay acceptance.
